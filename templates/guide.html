How the pursuit agent reasons, and what we measured

EVE drifts around a 14×14 grid while WALL-E hunts her on a battery. WALL-E never sees her. It sees noisy bearings and signal strengths, some of them from decoy beacons, and keeps a probability for every cell.

One tick, five moves

Numbers in magenta are read from a recorded run (seed7_v2_standard), not typed in.

Drift

EVE moves with probability q; time advances before WALL-E acts.

q ∈ {0.05, 0.12, 0.20}
by threat level

Predict

Smear the belief across her possible steps. Mass is conserved.

p′ = (1−q)p + q·Σ p(n)/deg(n)

Read

A scan returns unlabeled detections: EVE plus every decoy, shuffled.

s = a·e^(−d/5) + noise
θ = bearing + noise

Weigh

Marginalise over which detection is EVE, then multiply and renormalise.

L(c)=ε+Σⱼ wⱼ·N(θⱼ)·N(sⱼ)
post ∝ prior·L, own cell ×0.06

Spend

Pick the next action under the battery rule.

reserve = path(pad) + 2·3
spend only if slack ≥ 0

What v2 changes

Each change is a switch in the agent registry, so the benchmark below can credit it individually.

Learns EVE's speed.

Five beliefs run at different q and are re-weighted by how well each predicted the readings.

Exact decoy handling.

Instead of a heuristic match score, it computes the probability that each detection is EVE by summing over all ways to assign detections to the known decoys.

Scans where information is cheap.

Monte-Carlo expected information gain per battery unit, over cells it can reach and still get home from.

Reserve from the destination.

Before committing to a leg it checks the way home from where the leg ends, not from where it stands.

Aims at the cell that minimises expected travel.

Not the tallest peak: the cell with the smallest probability-weighted distance to all of EVE's possible positions.

Checks itself.

A 400-particle filter shadows the grid and surprising readings are tempered. Neither uses the hidden truth. In our benchmark runs neither ever fired, so treat them as safety diagnostics, not a measured gain.

Measured

Paired seeds: every agent faces the same map, the same EVE path and the same sensor noise. Tuning used other seeds. Source: results/LEADERBOARD.md.

Limits

The agent knows the decoy positions; it does not have to find them. The reference-style baseline is our re-implementation from a public description, not the original code. The expected-information estimate ignores decoys when planning scans. Learning q helped only slightly (it is weakly identifiable from bearings). The biggest single gain came from the capture-oriented target, and v2 pays for its speed with a slightly worse belief (log loss 2.39 against v1's 2.29) because it scans less. Results hold for this sensor model and these map sizes.
